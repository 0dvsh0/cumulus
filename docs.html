Documentation

Cumulus audits how easily AI agents can discover, access, understand and buy from a website. It fetches raw HTML, renders the page in headless Chromium, then walks the links the way a task-driven agent would — find pricing, extract plans, locate signup and docs, reach checkout — and produces a score out of 100 with evidence for every check.

The dashboard UI and the programmatic interfaces (REST, MCP) consume the same reports: one engine, one data model.

What an audit does: reads robots.txt, fetches public pages (≤14), renders the homepage and pricing (when found) in Chromium, runs 5 navigation-only agent tasks, then scores 33 checks. It never fills or submits forms, never creates accounts, never pays, and respects robots.txt — checks it cannot run because of robots or challenges are reported as Blocked, never as failure.

Quickstart

Start an audit with one POST. The response is an audit id; progress streams over SSE; the finished report lands on the record endpoint.

start + watch + report
curl -s -X POST http://localhost:3000/api/v1/audits \
  -H 'content-type: application/json' \
  -d '{"url":"https://example.com"}'
# → {"id":"a5f3…","status":"running","pct":2,…}

curl -N http://localhost:3000/api/v1/audits/a5f3…/events
# event: progress {"stage":"Reading robots.txt","pct":14,…}
# event: done     {"status":"complete","report":{…}}

curl -s http://localhost:3000/api/v1/audits/a5f3… | jq .report.score

A finished audit is available at /report/<id>. The zip your team ships is GET /api/v1/audits/<id>/fix-kit.

MCP (Model Context Protocol)

An MCP server is mounted at POST /mcp using JSON-RPC 2.0 (streamable-HTTP style, stateless). Tools:

ToolInputReturns
start_audit{url}Audit id to poll
get_audit_status{id}Stage, percent, readiness
get_report{id, terse?:bool}Score, categories, coverage, per-check evidence, journey, stats
list_findings{id, severity?:word}Failures/partials with evidence; blocked/inconclusive items under openItems
get_fix_kit{id}Zip download URL + contents description
check_catalogue{}The 33 checks + scoring model

Desktop agents speak stdio; use the bundled bridge (scripts/mcp-stdio.mjs, line-delimited JSON-RPC over stdin/stdout):

claude-style client config
{
  "mcpServers": {
    "cumulus": {
      "command": "node",
      "args": ["<path>/scripts/mcp-stdio.mjs"],
      "env": {
        "CUMULUS_MCP_URL": "http://localhost:3000/mcp",
        "CUMULUS_API_KEY": "…"
      }
    }
  }
}

Status semantics

Seven outcomes. Only three move the score. An untested check is never a failure.

StatusCreditMeaning
Pass1.0Verified working with evidence.
Partial0.5Works with caveats (thresholds partially met).
Fail0Verified broken.
Blocked—Couldn't test: robots.txt disallow, challenge page, or a prerequisite failed (e.g. pricing never found).
Inconclusive—Tested, but the evidence didn't settle it (e.g. 429 rate limit).
Error—The audit itself hit a network/timeout failure for this check.
N/A—Genuinely doesn't apply (e.g. no pricing surface on a non-commercial site) — excluded from coverage.

Scoring model

weight critical 5 · high 3 · medium 2 · low 1 category Σ(weight × credit) ÷ Σ(weight of evaluated checks) overall mean of category scores with ≥1 evaluated check coverage tested weight ÷ applicable weight ← blocked/inconclusive/error are applicable, n/a is not

Coverage is always shown beside scores: a 90 made of one lucky check is not the same as a 90 made of thirty. Categories with nothing evaluated report n/a and don't drag the mean.

Safety model

Every submitted URL is treated as untrusted. Cumulus reads; it never writes.

  • SSRF guards: IP literals, private/loopback/link-local/CGNAT and reserved ranges, internal hostnames (localhost, *.local, *.internal…), non-standard ports, URLs with embedded credentials — all refused before any request is made. DNS is resolved once, validated, and the connection is pinned to the validated address, so a rebinding race can't bounce a fetch inward. Every redirect hop is re-validated.
  • Browser containment: headless Chromium runs with a default-deny DNS resolver (--host-resolver-rules) plus a per-request route guard that re-checks every URL the page tries to load.
  • robots.txt: parsed and honoured for every fetch whose purpose is to simulate agents. Disallowed paths produce Blocked results with the reason — never silent failures.
  • Limits: total wall-clock budget (150 s), ≤ 14 crawl pages, response size caps (3 MB raw / 6 MB decoded), per-request timeouts, politeness delays, ≤ 3 concurrent audits, 20 s per-origin cooldown.
  • Never writes: no form submissions, no account creation, no payments — checkout "success" is defined as a payment interface loaded, then the auditor stops.

Self-hosting

term
npm install          # also downloads Chromium (playwright)
npm start            # http://localhost:3000

# configuration (all optional)
PORT=3000
HOST=0.0.0.0                 # bind address
CUMULUS_API_KEY=…            # require bearer auth on /api + /mcp
CUMULUS_DATA_DIR=data        # audit history persistence (JSON lines)
CUMULUS_ALLOW_PRIVATE=1      # TEST-ONLY: allow local targets for development

Node ≥ 20. Chromium ships via Playwright. Reports persist under CUMULUS_DATA_DIR/audits.jsonl; the in-memory index keeps recent records hot.
